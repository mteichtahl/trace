# Rules for agents on the trace sample

This repository is a demonstration: a small, finished board that exists to exercise trace. Keep it working.

- Never weaken a check to make it pass. If a simulation, DRC or test fails, report why, and fix the design or the
  model only when the issue asks for it.
- The KiCad files in `hardware/` and `layout/` are generated by `tools/generate.ts`. Change the generator and
  regenerate; never hand-edit the board or schematic. ERC and DRC must stay at 0 errors.
- `layout/` is the same board with no copper on purpose: it is pcb.autoroute's input. Write routed results beside it
  (`*.routed.kicad_pcb`), never over `hardware/`.
- TRC-OPA1 and TRC-TMP1 are fictional parts. Their datasheets in `docs/datasheets/` were written for this sample.
  Never present their figures as a real vendor's, and keep every citation of them marked as fictional.
- Figures typed in from memory stay `verified: null` until a datasheet page in the library backs them.
- Hardware tools run only against the bench emulator (`trace hil emulate`), with TRACE_HARDWARE=1. There is no real
  instrument here.
- Long runs (Blender renders, openEMS, CalculiX, OpenFOAM, the routers) go to the GPU or CPU job queue. Keep render
  sizes small (at most 800 x 500, 32 samples) so a run costs cents.
- Comment the numbers you measured on the issue, with the run ids, then close it.
