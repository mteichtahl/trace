# trace web app

The single-page app designed in [docs/ui-design.md](../docs/ui-design.md), wired as [docs/web-build.md](../docs/web-build.md) says.
React 19, Vite, TypeScript (strict), Tailwind CSS v4, shadcn/ui (new-york, neutral), TanStack Router (file routes), TanStack
Query, TanStack Table, CopilotKit v2 over AG-UI.

## Run it

```sh
cd web
npm install
VITE_API_ORIGIN=https://<your trace CloudFront address> npm run dev   # /api is proxied there
npm run dev:mock                                                    # no backend: fixtures (src/mock/), signed in as an admin
npm test                                                            # vitest + Testing Library (jsdom)
npm run build                                                       # tsc -b && vite build → web/dist
npm run screenshots                                                 # with dev:mock running: Playwright shots into screenshots/
```

From the repository root: `npm run build:web`, `npm run test:web`.

**Mock mode** (`VITE_MOCK=1`, development only) replaces `fetch` for `/api/*` with `src/mock/handlers.ts`, answering every action
the built screens call from `src/mock/fixtures.ts`, including sign-in (any email; the passkey and email-code choices sign in, the
password asks for a TOTP code — any six digits) and a streamed AG-UI reply at `/api/agui`. `main.tsx` only imports it behind
`import.meta.env.DEV`, so it is never in a production build. Add a case to `action()` when a new screen calls a new action.

## Adding a screen

1. **Route file.** Create `src/routes/_app/<path>.tsx` (with the shell) or `src/routes/_focus/<path>.tsx` (Focus mode). The
   router plugin regenerates `routeTree.gen.ts` when `npm run dev` or `npm run build` runs. A placeholder may already exist
   (`NotBuilt`, or the project catch-all `routes/_app/p/$id/$.tsx`): replace it. For a project tab, add
   `routes/_app/p/$id/<tab>.tsx` — it wins over the catch-all — and its tab already shows in `visibleTabs()` (`p/$id.tsx`).

   ```tsx
   export const Route = createFileRoute('/_app/p/$id/evidence')({
     staticData: { crumb: 'Evidence' },          // the breadcrumb; useCrumb(routeId, label) to set one at run time
     validateSearch: z.record(z.string(), z.unknown()), // only when a Data table keeps its view in the address
     component: Evidence,
   })
   ```

2. **Data.** Read with `useAction('<action>', args)` or `useQuery(q('<action>', args))` (`lib/queries.ts`); every action and its
   types are in `lib/api.ts` → `Actions` (add a new one there first). Write with `useCall('<action>', (args) => [keys to
   invalidate])`. Never poll: the live connection invalidates by `[action, repo]` prefixes (`lib/live.ts`
   `invalidationsFor`), so key new reads the same way (`q()` does) and add the event mapping when a new kind of record changes.

3. **States.** Every screen draws all five: `Loading` (skeletons after 150 ms; show cached data at once), `EmptyState` (one sentence
   and the action that fills it), `Partial`, `QueryError` / `ErrorState` (what happened, whether anything was lost, Try again,
   detail folded), and the shell's `OfflineBanner`. A project the person cannot see is `NotShared` (same words whether it exists).

4. **Context for trace.** `useTraceContext({ label, description, value }, key)` tells the agent what is on screen and shows a
   removable chip in Ask trace. Use the key `'project'` with `value: { repo, … }` for the project in view (the panel picks its
   threads from it), `'screen'` for the screen, and your own for a selected item.

5. **Layout.** `<Column>` (the 960 px reading column) or `<Column wide>`; `<Section label="…" count={n} action={…}>` for the
   "NEEDS YOU" style headings. Phones: test at 390 px; tables turn into cards on their own.

6. **Mock.** Add fixture data and a case in `src/mock/handlers.ts`, so the screen renders under `npm run dev:mock`.

7. **Tests** sit beside the code (`*.test.ts(x)`), run in jsdom; see `components/data-table/data-table.test.tsx` for the pattern
   with a QueryClient.

Reference screens: Home (`routes/_app/index.tsx`), Projects (`routes/_app/projects/index.tsx`: a DataTable with columns,
URL view and row click), Project overview (`routes/_app/p/$id.tsx` + `p/$id/index.tsx`), and a Focus-mode frame
(`routes/_focus/p/$id/do/$skill.tsx`).

## Conventions

- **Words.** Plain and contextual (“Sign the schematic gate”, not “Approve”). Summaries from the API use `**bold**` for the
  recommendation; render them with `<Rich>`. Wrap technical words in `<Term>` or text in `<Explained>`.
- **Colour.** The accent (`primary`) only for the person's move. Status always as `<StatusBadge>` (icon + word).
- **Requests.** Always through `call()` / `api()` (`lib/api.ts`): they add the bearer token and the `x-amz-content-sha256` body
  hash CloudFront's origin access control needs on POST/PUT, and refresh once on 401. Tokens live in memory only.
- **Heavy code is lazy.** Markdown/KaTeX, Shiki (per language), Mermaid, Recharts and QR load on first use; keep new viewers
  (KiCanvas, PDF.js, three.js, Cytoscape) behind `lazy()`/`import()` too. Register file viewers with `registerFileViewer()`.
- **Chat.** CopilotKit v2 with trace's agent as a self-managed AG-UI `HttpAgent` at `/api/agui` (no CopilotKit runtime; the web
  backend checks access on every request). Tool calls draw by result shape (`chat/renderers.tsx`); `ask_person` is the
  human-in-the-loop Decision card.
